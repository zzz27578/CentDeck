# 对话窗口、便签拖动与模型连接修复

## 实际问题与原因

- 编辑便签拖动时，小便签带有 `sel`，样式将它隐藏；拖动又关闭编辑卡片，导致中途没有任何可见便签。现在只在编辑卡片实际打开时隐藏小便签，拖动立即恢复显示；取消拖动恢复原位。
- 聊天记录原本以助手 ID 为唯一键。同一助手无法拥有独立对话，新请求会继承最近 12 条历史。
- 左侧预览的刷新条件包含任务 ID；项目已有文件提交时，增加一条纯聊天任务也会触发刷新。现在只比较实际提交集合。
- 原运行层将 `pending` 和历史消息中的 `tool_calls` 指向同一数组，执行时 `shift()` 清空历史调用。这不仅使日志缺少工具名，也可能让后续请求带有无法匹配的工具结果。现在使用独立副本。

## 慢回复的本机记录

余白项目中，2026-10-01 的实际输入为“你好，收到恢复111”。该轮耗时 **133.367 秒**，进行了 **4 次模型请求、4 次工具调用**，思考档位为 **xhigh**。工具结果中有多份项目上下文和任务统筹技能正文；最终回复混入此前“蓝色标记、年后、大肥鱼”的内容。

原因包括无条件要求“先读取 project_context”的平台规范、同一助手自动继承旧历史，以及较高的思考档位。旧日志未记录逐次请求耗时，不能据此分离服务商排队、模型思考与网络传输各自的时间。没有擅自降低用户选择的思考强度。

修复后：

- 平台技能按当前意图使用，问候和确认不要求检查项目；已读且未变化的上下文不重复读取。
- 对明确问候及简短指定文字回复使用轻量上下文，不发送项目工具与项目技能正文；模糊请求仍保留正常项目能力。模型意外返回工具调用时不会执行。
- `project_context` 不再把聊天记录及其嵌套请求重新注入模型，只返回项目资料与最近任务摘要。
- 保存每次模型请求耗时及输入 token 估算，便于后续区分平台调用链和接口等待。
- OpenAI Compatible 支持实际 SSE 流式回复；仍返回 JSON 的兼容接口可正常显示最终结果。Gemini 原生及外部 MCP 保留原有传输方式。

## 对话与界面变更

- 新增项目级会话 ID，同一助手支持多个独立对话和多个悬浮窗口；旧助手聊天自动迁移。
- 顶部“新对话”、项目对话列表、重命名、删除、独立窗口打开。原“任务 / 正在发生”页面替换为可搜索的“对话历史”。删除聊天不会撤回已经保存的网页修改，仍在运行的回复会停止。
- `@` 可指定实际回复助手，保留当前会话历史与引用；使用被指定助手的角色、提示和技能。模型与思考强度会先采用其配置，发送前仍可调整。
- 消息增加头像、复制、编辑和重新生成。编辑/重试创建新分支，保留原记录与已保存的网页；此前消息作为分支快照，不再跟随原任务更新。
- 思考、输出、使用工具、等待外部接管、暂停或错误，均在头像旁显示。提供停止、继续、重试及直接回答澄清问题的入口，移除工具次数横条。
- 上下文折叠区显示最近消息条数、当前模型与引用、范围，以及上次实际请求的输入估算。最近 12 条消息用于下一次普通请求；估算值不是模型容量占比。
- 离开当前对话后仍接收后台回复并写入归档，回复不会混入新窗口。助手切换列表增加头像和紧凑字号。
- 模型提供商表单重排为连接设置和模型能力两组，支持密钥遮蔽/明文切换。使用非密码字段加遮蔽样式、关闭自动填充提示，减少 Edge 的登录表单误识别；浏览器扩展仍可能自行介入。密钥字段继续受 MCP 私密字段规则保护，已保存密钥不会回传。

## 验证

在隔离项目、临时配置、独立 Chromium 和本机模拟流式模型中验证，未调用用户的付费接口、未改写用户配置：

- 真实鼠标拖动：在松手前检查便签可见性和位移。
- 旧聊天迁移、新对话隔离、同助手多窗口、历史编辑分支。
- “收到请回复111”仅一次模型请求、零工具调用；即使有历史页面提交，预览 iframe 也不重建。
- 流式消息及头像状态，停止后忽略迟到结果，指定助手实际接收请求。
- 普通文件读取保留完整工具调用历史，逐请求耗时正常记录。
- 切换窗口后的后台完成、历史搜索、重命名、删除、刷新后不复现已删除对话。
- 320 px 助手栏不横向溢出，发送和模型控件在同一行。
- API Key 小眼睛、默认遮蔽及关闭自动填充标记；亮暗表单截图检查。
- 原有 Agent 集成 26 组、提供商、外部运行层、MCP 传输、Skills、工作台状态、便签编号及前端语法回归通过。

新增测试：`tests/conversations.test.mjs`、`tests/conversations-browser.test.mjs`。截图：`docs/screenshots/chat-conversations-light.png`、`conversation-history-light.png`、`provider-editor-light.png`、`provider-editor-dark.png`。
