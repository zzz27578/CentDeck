# 余白项目：MCP 外部用户实测与设计更新

后续针对以下缺口的修复及验证见 [MCP 实测问题修复](MCP实测问题修复_2026-10-01.md)。本文件保留最初实测记录。

## 实测方式

通过标准客户端进程启动 `server/mcp-stdio.js`，执行 initialize、通知、工具发现及 tools/call。适配器自行读取本机连接凭证；没有把凭证放到报告中，也没有使用直接文件写入绕过项目 MCP。

发现本机 8420–8423 四个服务可连接，实际浏览器工作台位于 8423，打开项目为 `yubai-mcp`。先调用 list_projects、project_context、read_skill、read_page；项目无页面或元素锁。待提交内容在 examples/yubai 中准备，真实项目修改经 MCP patch_text / write_files 完成。

## 设计更新

- 保留米白、靛蓝与独立工作室定位，采用更清楚的编辑式排版与留白。
- 首页新增折纸字母主视觉，作品采用有节奏的双列布局；茶包装与数字界面展示更完整，过滤保留真实行为。
- 案例页补充品牌字体/色彩系统、数字界面展示和项目设计说明。
- 服务页统一三项服务、四步流程、FAQ 和咨询入口。
- 三页共用导航、页脚、咨询弹窗。手机导航可展开，支持 Escape 收起；弹窗关闭恢复焦点，输入内容只在本地生成摘要。
- 统一 style.css 与 design/tokens.json，移除服务页原有的大段独立内联样式。无远程字体、图片或脚本依赖。

## 好用与不足

文件读取、版本化提交、事务拒绝和标记撤销可用，关键结果有明确回执。用真实项目做设计修改的核心路径能够完成。

仍有以下使用缺口：

1. read_page 能读 DESIGN.md，但 write_files 的允许类型不含 Markdown。说明文件不能通过同一工具更新。此次 live 项目的 DESIGN.md 保留原样；examples 中提供新的设计说明供交付。
2. 浏览器刷新会更换 clientId。一次刷新操作等到超时后，重新调用 ui_state 才发现新客户端并恢复。稍后还观察到一次暂时没有在线客户端的返回；服务文件操作不受影响。
3. ui_state 只返回工作台外层控件，不提供页面截图、布局尺寸、网页 iframe 内的按钮或表单内容。因而 MCP 控件回执不能独立完成“作品筛选、咨询表单、页面视觉”的完整验收。
4. 项目工具的 Schema 虽允许 projectId，却没有把它列入 required；外部模型需要额外阅读平台指南才知道哪些工具必须指定项目。
5. write_files 的 title 参数只用于新增页面，已有页面的项目清单标题没有随 HTML 标题更新，仍显示原有 index/case；工具没有独立重命名页面元数据的入口。

这些问题在此轮记录，没有为测试便利擅自改变 MCP 权限、工具实现或本机认证。

## 验证边界

tests/yubai.test.mjs 检查三页唯一 ID、标题、视口声明、本地资源和跨页锚点，并执行真实 script.js 的事件处理器，验证作品筛选、手机菜单、Escape/链接收起、弹窗关闭焦点和本地表单摘要。JavaScript 语法检查通过。

这些属于代码级检查。MCP 已实际控制工作台并回传视图、标记与手机尺寸，但没有提供截图或网页内部点击证据，故不声称完成三页的浏览器视觉验收。
