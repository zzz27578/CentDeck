# 技术架构与三步计划

> 2026-10-01 收尾说明：本文保留原始产品愿景与路线图。当前实现、验证证据及尚未实现项以 [收尾验收](收尾验收.md) 为准；本轮外部接管对象按用户确认使用 DeepSeek Harness，不以 Hermes Agent 替代。
> 这份文档回答三个问题：
>
> 1. 整体用什么结构来搭？答案是"主体 + 插件"。
> 2. AI 怎么接进来？内置助手、MCP 接口、技能与规范三者配合。
> 3. 分三步具体做什么？
>
> 产品是什么、为什么要做，请看 [项目说明书](项目说明书.md)。

## 一、要点汇总

1. **主体 + 插件。** 主体只做最核心、必须稳定的事，其余功能都做成插件。我们自己的草图模式、便签、素材库也按插件的方式来写，这样可以证明插件接口真的够用，别人二次开发时也能照着写。
2. **三类扩展，各管一件事。**
   - **插件管"功能"**：给工作台加面板、工具、检查项、导入导出。
   - **技能（Skills）管"知识"**：告诉 AI 怎么做事，比如施工规范、某种艺术风格。
   - **MCP 管"对外接口"**：让外部 AI 来操作工作台。
3. **一套工具，两种用法。** 工作台的能力（读页面、看选中内容、改字、加标记……）统一登记成"工具"。内置助手，和外部的 Claude Code、Codex、Hermes Agent 等，调用的是同一套工具。锁定、三灯判定、撤销都在工具这一层把关，不管谁来改都绕不过去。
4. **不自创格式，采用开放标准。**
   - 技能用 Agent Skills（SKILL.md），对外接口用 MCP，项目说明用 AGENTS.md，设计规范用 W3C 设计令牌格式（DTCG）加 DESIGN.md。
   - 这样别人写的技能能直接装进来，我们的规范也能直接给别人的 AI 用。
5. **需要一份自己的规范。** 这份"官方技能包"教 AI 怎么在工作台里干活，内容包括施工规范、三灯规则、工具用法。有了它，外部 AI 接管时也不会乱写。
6. **需要一个技能库。** 在本地管理技能的安装、启用、停用，可以从 skills.sh、GitHub、压缩包安装，艺术风格类的技能单独一栏。先接入现有生态，不自建大市场；来路不明的技能要先检查再装。
7. **项目就是一个文件夹。** 网页源码、设计规范、标记、便签、锁定、技能都以普通文件存放。好处有三个：
   - 能用 Git 管理版本；
   - 外部 AI 可以直接读；
   - 导出就是打包这个文件夹，不会被工具绑死。
8. **丝滑优先，省 token。**
   - 先定下性能指标：拖动每秒 60 帧，点击后 0.1 秒内有反馈，改完 1 秒内刷新。
   - 第一步完全不用模型；第二步起，每次调用都要按需加载、只发必要的内容。
9. **分三步走。**
   - 第一步：把查看、修改、草图、便签、素材导入这些基础功能打磨丝滑，不接任何 AI。
   - 第二步：把工作台的工具注册给 AI，接入内置助手和 MCP，明确技能和规范。
   - 第三步：开放插件生态，完善导出和应用，整理总结。

## 二、整体架构：主体 + 插件

```
┌ 界面层：总览画布、单页编辑、属性面板、草图工具、便签、素材库……（大多是插件）
├ 扩展层：插件宿主、工具注册表、技能库、MCP 接口
├ 内核：项目模型、门牌号（源码映射）、命令总线、回写引擎与三灯判定、锁定与权限、预览宿主、文件读写
└ 项目文件夹：网页源码、设计规范、标记、便签、锁定清单、启用的技能
```

### 1. 内核只做这几件事

| 模块 | 负责什么 | 为什么必须放在内核 |
|---|---|---|
| 项目模型 | 页面、元素、跳转关系、标记、便签、锁定 | 所有功能都要读写它 |
| 门牌号（源码映射） | 把画面上的元素对应到代码位置 | 指认和回写的基础 |
| 命令总线 | 所有修改都变成一条"命令"，可以撤销、可以记录 | 不管是手改、插件还是 AI，改动都走同一条路 |
| 回写引擎与三灯判定 | 把修改翻译成代码，并判断能不能安全写回 | 核心创新，必须统一 |
| 锁定与权限 | 规定谁能改什么 | 安全底线，不能交给插件 |
| 预览宿主 | 运行网页、热更新 | 画面和代码要始终一致 |
| 文件读写 | 读写项目文件夹，监听外部改动 | 外部 AI 直接改文件时，工作台也能察觉 |
| 插件宿主和工具注册表 | 加载插件、登记工具 | 扩展的入口 |

### 2. 插件能扩展什么

| 扩展点 | 例子 |
|---|---|
| 面板 | 图层面板、代码面板（给依赖手写代码的人）、时间轴 |
| 画布工具 | 画笔、箭头、测量尺 |
| 属性编辑器 | 字体、颜色、阴影、动画预设 |
| 检查项 | 对齐、可读性、SEO、无障碍 |
| 框架适配器 | React、Vue、Svelte 项目的门牌号和回写 |
| 导入与导出 | 导入网页文件夹、设计稿；导出静态网站、推送到 GitHub、一键部署 |
| 素材来源 | 本地图库、图库网站、生图接口 |
| 模型服务商（第二步） | 接入各家模型 |
| AI 工具（第二步） | 插件把自己的能力登记成工具，AI 就能调用 |
| 技能包 | 插件可以附带技能，装插件时一起装上 |
| 模板与风格预设 | 页面模板、设计规范预设 |

### 3. 插件长什么样

- **一个文件夹 + 一份说明书（manifest）。** 说明书写明：名字、版本、需要哪些权限（读项目、写项目、联网、读写文件）、扩展了哪些扩展点、什么时候加载。
- **按需加载。** 用到时才启动，不拖慢主体。这借鉴了 VS Code 的"激活事件"。
- **沙箱运行。** 插件跑在隔离环境里，通过消息和主体通信，插件崩溃也不会拖垮主体。这借鉴了 Figma 插件的做法。
- **修改必须走命令总线。** 插件改的东西同样能撤销，同样受锁定和三灯判定约束。
- **分两步开放。** 第一步先在内部定好接口，自己的功能都按插件写；第三步再对外开放，同时提供开发文档和插件模板。

**例子：手写代码插件。** 给依赖手写代码的人加一个代码面板（基于 Monaco 或 CodeMirror），画面和代码双向同步：点画面上的元素，代码跳到对应的行；改了代码，画面立刻刷新。它本质上只是一个"面板"加一个"框架适配器"，不需要改动主体。

## 三、AI 怎么接进来（第二步做，第一步先把接口留好）

### 1. 三种接法，同一套工具

| 接法 | 适合谁 | 怎么用 |
|---|---|---|
| 内置助手对话框 | 不想折腾的人 | 在工作台里直接对话，填好 Key 就能用（多模型接入见项目说明书第七节） |
| MCP 接口 | 已经在用 Claude Code、Codex、Cursor、Hermes Agent 等工具的人 | 工作台在本机开一个 MCP 服务，这些工具连上后，调用的是同一套工具 |
| 直接改文件（兜底） | 外部 AI 不走 MCP，直接改源码 | 工作台监听文件变化，自动刷新并做检查；碰到锁定元素就提醒，可以一键还原 |

**为什么要一套工具两种用法**：功能只写一遍，内置助手能用的，外部 AI 也能用。更重要的是，锁定、三灯判定、撤销都放在工具这一层，外部 AI 也必须遵守，不会出现"内置助手守规矩，外部 AI 乱改"的情况。

**"指认"也能传给外部 AI**：你在工作台里点选、圈选、画标记，外部 AI 调用 `get_selection` 或 `get_marks` 就能拿到这些内容，包括门牌号、截图和你写的要求。你不用再把"右边那个按钮"描述给 Claude Code 听。

### 2. 工具清单（草案）

| 类别 | 工具 | 作用 |
|---|---|---|
| 看 | `get_project_overview` | 页面列表、跳转关系、设计规范摘要 |
| 看 | `get_page` | 某一页的结构摘要，外加贴在各块上的长期规则（不是整页代码） |
| 看 | `get_selection` | 你当前选中、圈选的内容 |
| 看 | `get_marks` | 草图标记和任务单 |
| 看 | `screenshot` | 某一页或某一块的截图，需要时才调用 |
| 看 | `get_design_spec` | 设计规范 |
| 改 | `edit_text`、`edit_style`、`move`、`insert`、`remove` | 对应手动修改的各项操作，同样经过三灯判定 |
| 改 | `apply_patch` | 较大的代码修改；提交后先检查锁定和规范 |
| 管 | `propose_change` | 大改动先作为"提案"，你点接受才写入 |
| 管 | `resolve_mark` | 处理完一条标记后打勾 |
| 管 | `run_checks` | 跑质检：对齐、色卡、可读性、锁定 |

工具返回的都是**摘要加门牌号**，不是整页代码；AI 需要细节时再追问。

### 3. 省 token 的设计

- **工具少而精**：只做十几个"粗粒度"工具，不做上百个小工具。工具说明本身就占 token。据 Anthropic 的文档，常见的五个 MCP 服务一起接上，光工具说明就要约 5.5 万 token，模型还一个字都没开始干活。
- **结果只给摘要**：先返回结构摘要和门牌号，截图按需调用。
- **按需加载**：工具多了以后，支持"工具搜索、延迟加载"（Anthropic 实测这种做法能省约 85% 的 token）。技能也一样：先只加载名字和一句话描述，用到时才读全文。
- **稳定排序，方便缓存**：固定内容放在请求最前面，工具列表顺序保持不变，这样模型的提示缓存更容易命中。2026 年 7 月的 MCP 新版规范也要求服务端按固定顺序返回工具列表，就是为了保住缓存。
- **任务单代替整页代码**：演示中，一份含 3 条标记的任务单约 900 字，整页代码约 5400 字。

### 4. 安全

- 锁定、权限、三灯判定都在工具层执行，外部 AI 也绕不过去。
- 外部 AI 的写操作默认先进"待确认"区，你点接受才写入；也可以设成自动接受。
- 所有 AI 改动都记进撤销历史和版本记录。
- MCP 服务只在本机监听，连接时需要配对口令。

## 四、技能与规范（重点设计）

### 1. 结论：要做，但用开放标准

**Agent Skills 是什么**：Anthropic 在 2025 年 12 月把它发布为开放标准。一个技能就是一个文件夹，里面放一份 SKILL.md，开头写名字和一句话描述，后面是给 AI 的说明，还可以附带脚本、参考资料和素材。

**为什么选它**：

- **通用**：Claude Code、Codex、Cursor、Gemini CLI、VS Code 等三十多个工具都支持，Hermes Agent 也兼容。同一个技能，拿到这些工具里都能原样使用。
- **省 token**：AI 启动时只读每个技能的名字和描述（每个约 30–50 token），真用到时才读全文。
- **和 MCP 分工明确**：MCP 给 AI"手"（能调用哪些工具），技能教 AI"方法"（这些工具该怎么用）。

### 2. 我们提供的四份规范文件

| 文件 | 格式 | 内容 | 谁来用 |
|---|---|---|---|
| 官方技能包 | Agent Skills（SKILL.md） | 施工规范（统一写法，方便回写）、三灯规则、工具用法、处理标记的流程 | 内置助手和所有外部 AI |
| `AGENTS.md` | 开放约定 | 这个项目的说明：技术组合、目录结构、禁止事项、锁定清单放在哪 | 外部 AI 打开项目时会先读 |
| `design/tokens.json` | W3C 设计令牌格式（DTCG） | 颜色、字号、间距、圆角等 | 程序检查、导出，以及 Penpot 等设计工具 |
| `DESIGN.md` | Markdown | 设计规范的"人话版"：风格、质感、用法示例 | AI 和人都能读 |

贴在各块上的长期规则存放在项目文件里。AI 通过 `get_page`、`get_selection` 读取某一块时，会一并拿到这块的规则。

### 3. 技能库：存放和管理下载来的技能

- **分类**：
  - 官方：我们维护的技能；
  - 风格：艺术性技能；
  - 工作流：比如"做落地页""做表单"；
  - 我的：自己建的技能。
- **来源**：可以从 skills.sh、GitHub 仓库、压缩包或本地文件夹安装；也能打包分享，格式兼容 skills.sh 的技能包。
- **作用范围**：可以全局启用（所有项目），也可以只在某个项目启用。项目里启用的技能会一起存进项目文件夹，换电脑、交给外部 AI 时都带着走。
- **安全**：技能里可能带脚本，所以：
  - 安装前先展示它包含哪些文件、需要什么权限；
  - 带脚本的技能默认不执行脚本；
  - 推荐列表只收可信来源。

  这不是多虑：skills.sh 没有人工审核，安全研究者曾绕过它的恶意技能检测。

### 4. 艺术性技能

艺术性技能本质上是"风格技能"，由四部分组成：一份设计规范预设（tokens）、风格说明、示例页、禁忌清单。

- 装上后会出现在定调环节的"风格"选项里，一键套用到设计规范，再按需微调。
- 例子："瑞士国际主义""电子杂志""新中式""暗黑科技"。
- 第一步没有 AI，也能用它的设计规范预设；第二步起，AI 会按它的风格说明来做。

### 5. 自建技能

- 提供表单式编辑器，填这几项就行：名字、什么时候用、要点、示例。保存下来就是标准的 SKILL.md。
- 可以从当前项目的设计规范"一键生成风格技能"，下一个项目直接用。

### 6. 插件、技能、MCP 的分工

| | 插件 | 技能 | MCP |
|---|---|---|---|
| 是什么 | 代码 | 说明书（文字，可以附带脚本） | 接口 |
| 给谁用 | 工作台 | AI | 外部 AI |
| 解决什么 | 给工作台加功能 | 教 AI 怎么做 | 让外部 AI 能操作工作台 |
| 例子 | 代码面板、时间轴 | 施工规范、瑞士风格 | 选中、改字、截图等工具 |
| 花不花 token | 不花 | 用到时才花 | 调用时才花 |

三者可以组合：一个插件可以同时附带技能、登记工具。例如"动画插件"提供时间轴面板（插件），附带"动画写法"技能，还登记了 `set_animation` 工具，AI 就能直接调动画。

## 五、丝滑与轻量：产品本身的体验要求

### 1. 性能指标

| 场景 | 指标 |
|---|---|
| 冷启动到能用 | 3 秒以内 |
| 悬停、点击选中后的反馈 | 0.1 秒以内 |
| 拖动 | 每秒 60 帧，不掉帧 |
| 改完到画面刷新 | 1 秒以内（演示里已经做到） |
| 总览 50 个页面 | 缩放、平移不卡 |
| 撤销、重做 | 立即生效 |

### 2. 技术做法

- **编辑层和网页分开。** 选中框、参考线、标记都画在网页上方的独立一层，不去改网页本身，演示里就是这样做的。
- **拖动时只改视觉位置，松手才写代码。** 拖动过程交给显卡合成，所以不卡；解析代码放到后台线程（Web Worker），界面不会被卡住。
- **总览画布上只有当前页是"活的"网页。** 其他页面显示缩略图，镜头靠近了再加载真网页。
- **插件按需加载**，不用的插件不占资源。
- **增量解析**：只重新解析改动过的文件。

### 3. 交互原则

- 常用操作不弹窗；所有操作都能撤销。
- 快捷键尽量沿用 PPT、PS 的习惯。
- 高级功能默认收起，装了插件才出现。
- 界面安静：少用颜色和动画，把注意力留给页面本身。
- 状态清楚：当前是查看、编辑还是草图模式，一眼就能看出来。

### 4. 控制模型消耗

- 第一步完全不调用模型。
- 第二步起：能手动的不调模型；调用前先预估花费；小模型优先；工具和技能按需加载；尽量用上提示缓存。

## 六、借鉴清单：开源项目取其精华

| 要做的事 | 借鉴谁 | 借什么 | 协议 |
|---|---|---|---|
| 门牌号（源码映射） | code-inspector、react-grab、Dyad 的组件标记插件 | 在编译时给元素注入源码位置 | MIT / MIT / Apache-2.0 |
| React、Vue 项目回写 | Onlook | 用语法树（AST）精确修改组件代码和 Tailwind 类名 | Apache-2.0 |
| 插件系统 | VS Code、Figma、GrapesJS、Penpot | 说明书 + 扩展点 + 按需激活；沙箱运行；插件接口的设计 | 只借设计 |
| 零件库 | Puck | 组件登记制，AI 只能用登记过的组件 | MIT |
| 页面地图画布 | 自研（原生 JavaScript + SVG） | 页面节点、按钮级连线、弹窗子卡片、框选引用 | — |
| 原型流程和浮层 | Penpot | 画板连线、用浮层模拟弹窗、多条流程 | MPL-2.0 |
| 设计规范格式 | Penpot（DTCG）、Google Stitch（DESIGN.md） | 标准格式，能和其他工具互通 | 开放格式 |
| 按屏幕调样式 | GrapesJS 的设备管理、Webstudio | 按屏幕宽度分别设置样式 | BSD-3；Webstudio 是 AGPL，只借思路 |
| 代码面板 | Monaco（VS Code 的编辑器）或 CodeMirror 6 | 手写代码插件的编辑器 | MIT |
| 选中元素交给 AI | Stagewise | 把选中内容、截图和结构信息打包给 AI 的方式 | AGPL，只借思路 |
| 双模型、角色和权限 | Aider、Cline、Roo Code、Hermes Agent | 规划和执行分开用模型；角色 = 模型 + 技能 + 权限（Hermes 的 Profile 也是这个思路） | Apache-2.0 / MIT |
| 多模型接入 | One API、LiteLLM | 统一的兼容接口 | One API 为 MIT；LiteLLM 需看具体模块 |
| MCP 服务 | MCP 官方 SDK | 直接使用 | MIT |
| 技能格式和分发 | Agent Skills 标准、skills.sh | SKILL.md 格式；兼容 `npx skills add` 的安装方式 | 开放标准 |

**用协议划一条线**：MIT、Apache、BSD 协议的库可以直接用；AGPL 项目只借思路、不复制代码，否则我们自己的代码也得开源；MPL 的代码改动部分要开源，需要按条款来。

## 七、技术选型建议（运行形态已确认，其余待确认）

| 部分 | 建议 | 理由 | 备选 |
|---|---|---|---|
| 语言与界面 | 原生 JavaScript（ES Modules），零依赖、免构建（2026-09-30 确认保持） | 双击就能用，不需要安装和打包 | — |
| 运行形态 | 本地端口服务（2026-09-29 已确认） | 本地程序监听本机端口：双击启动，自动在浏览器打开工作台，在终端里退出即停止监听；MCP 服务由同一进程提供，天然解决"纯网页没法在本机开 MCP"的问题；支持 Docker 一键部署 | 桌面套壳（Tauri / Electron）：已否决——双击启动的本地服务程序对目标用户已经足够，不值得付出打包、签名、自动更新的成本 |
| 模板格式 | 第一步只支持纯 HTML、CSS、JS | 最通用，回写最稳，演示已经验证 | React、Vue 做成适配器插件，第三步加入 |
| 项目格式 | 普通文件夹 + `project.json` | 能用 Git 管理，外部 AI 能直接读 | — |

项目文件夹的结构（草案）：

```
我的网站/
├─ project.json      页面、跳转关系、标记、便签、锁定清单
├─ AGENTS.md         给外部 AI 看的项目说明
├─ DESIGN.md         设计规范（人话版）
├─ design/
│  └─ tokens.json    设计规范（标准格式）
├─ skills/           本项目启用的技能
├─ assets/           图片、字体等素材
└─ src/              网页源码
```

## 八、三步计划

### 第一步：基础框架与展示（不接 AI）

**目标**：把"看、改、画、记、导入"打磨到极其丝滑，全程不调用模型。

| 模块 | 内容 | 验收标准 |
|---|---|---|
| 模板与导入 | 内置 2 个覆盖全部测试点的模板（四页官网、两页后台）；导入单个文件 / 多个文件 / 整个文件夹，逐页体检 | 任何写法的网页都能打开、查看；能改的直接改，改不了的说明原因并可交给 AI |
| 查看 | 总览画布（页面缩略图 + 自动识别的跳转连线）；单页编辑视图；手机、平板、电脑三种预览；放映 | 总览 50 页不卡；放映时能真实跳转 |
| 修改 | 选中（悬停轮廓、逐层选中、路径条、图层列表）；改字、字号、字体、颜色、粗细、微调、缩放、文本框、删除；吸附对齐、标尺、间距显示；三灯判定和指引；撤销、重做和版本历史；页面锁和元素锁 | 手改零 token；判定准确；撤销到底后与原文件完全一致 |
| 草图模式 | 画笔、箭头、方框、圆圈、便签钉、参考图（浮动图片）、橡皮；标记全局编号、锚定在元素上；导出任务单 | 标记不漂移；任务单能直接粘贴给任何 AI 使用 |
| 便签 | 一次性任务、长期规则 | 长期规则跟着元素走 |
| 素材 | 素材库；拖入图片、替换图片；图片自动压缩；导入字体（中文字体只打包页面上用到的字） | 换一张图一步完成 |
| 设计规范（手动版） | 风格预设；编辑颜色、字号、间距；导入、导出 tokens | 改一次规范，全站生效 |
| 内核与插件骨架 | 命令总线、项目格式、内部插件接口；草图、便签、素材库按内置插件实现 | 新功能能以插件形式加进来 |

**第一步就能派上用场**：虽然还没接 AI，但任务单可以直接复制，粘贴给你现在用的任何 AI。位置已经精确到代码行，AI 改完你再回到工作台查看、微调。

### 第二步：接入 AI（工具注册 + 技能与规范）

| 模块 | 内容 |
|---|---|
| 工具注册表 | 把工作台的能力登记成工具（见第三节的清单） |
| MCP 服务 | 在本机开 MCP 服务；一键生成 Claude Code、Codex、Cursor、Hermes Agent 等的连接配置 |
| 内置助手 | 对话框、@ 选择器、多模型接入、助手分工、花费控制（见项目说明书第七至九节） |
| 技能与规范 | 官方技能包、AGENTS.md、tokens.json、DESIGN.md；技能库（安装、启用、艺术性技能、自建技能） |
| AI 版功能 | AI 定调（问答、模仿参考图）、AI 出草图、生图素材；任务单一键交给 AI，改完自动写回 |
| 安全 | 待确认区；锁定在工具层执行；监听文件变化作为兜底 |

**验收标准**：

- 同一个任务，用内置助手和用外部的 Claude Code 都能完成，而且都改不了锁定的元素；
- 小改默认交给经济档；
- 官方技能包在 Claude Code、Codex 里能原样使用。

### 第三步：拓展与整理

| 模块 | 内容 |
|---|---|
| 插件生态 | 公开插件接口、开发文档、插件模板；插件目录 |
| 专业插件 | 手写代码插件（代码面板双向同步）、React 和 Vue 适配器、时间轴与滚动分镜、按屏幕调样式、SEO 与无障碍检查、分支 |
| 导出与应用 | 导出静态网站（压缩包）、源码项目、设计规范（tokens.json、DESIGN.md）、技能包、完整项目包（含标记、便签、锁定、历史）；一键部署或推送到 GitHub |
| 整理总结 | 用户手册、插件开发指南、技能编写指南、案例库 |

**验收标准**：

- 导出的网站脱离工作台也能直接上线；
- 导出的项目在 VS Code 或其他 AI 工具里能继续开发；
- 第三方照着文档能写出插件。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 插件太自由，拖慢或弄坏主体 | 沙箱、权限、按需加载；所有修改只能走命令总线 |
| 外部 AI 绕过工作台直接改文件 | 监听文件变化，自动检查，一键还原 |
| 第三方技能带恶意脚本 | 安装前审查；脚本默认不执行；推荐列表只收可信来源 |
| 工具太多，token 暴涨 | 工具少而精，结果只给摘要，按需加载 |
| 上游项目停更或改协议 | 只依赖开放标准和宽松协议的库；AGPL 项目只借思路 |
| 第一步打磨时间过长 | 每个模块先做到能用，再对照性能指标逐项打磨 |
