# 第一步实现约定（内部开发用）

本文件是第一步各模块并行开发时的"接口合同"，定下来的东西各方都必须遵守。
版本：v1.0 · 2026-09-29 · 状态：已完成（第一步 v1 已落地）

---

## 1. 运行形态（已定）

- 本地端口服务：原生 Node.js（`node:http`，零 npm 依赖），默认端口 `8420`，`PORT` 环境变量可覆盖。
- 双击 `CentDeck.bat`（Windows）或执行 `start.sh` → 启动服务 → 自动用默认浏览器打开 `http://localhost:8420` → 开始使用。
- 退出：在终端输入 `exit`、`quit` 或 `q` 回车，或 Ctrl+C；打印"CentDeck 已停止监听"后退出。
- Docker 部署属于第三步适配项，本阶段不做、不创建 Dockerfile；当前只保证本机（Windows）可直接运行。

## 3. 服务端 API（`server.js`）

统一 JSON：`{ ok: true, data: ... }` 或 `{ ok: false, error: "中文错误信息" }`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 工作台 `app/index.html`；`/app/*` 静态文件 |
| GET | `/api/templates` | 列出 `templates/` 下所有模板的 project.json 元信息 |
| GET | `/api/projects` | 列出 `projects/` 下项目 |
| POST | `/api/projects` | `{ template, name }` → 复制模板创建项目，同时生成原始快照 |
| GET | `/api/projects/:id` | 返回 project.json 内容（合并 design/tokens） |
| PUT | `/api/projects/:id` | 整体保存 project.json（标记、便签、锁定等） |
| GET | `/api/projects/:id/file?path=pages/index.html` | 读取页面源码（防路径穿越） |
| PUT | `/api/projects/:id/file` | `{ path, content }` 写回页面源码；写入前自动存历史快照 |
| GET | `/api/projects/:id/history` | 历史快照列表（时间、说明、文件） |
| POST | `/api/projects/:id/history/:hid/restore` | 恢复某个历史快照 |
| POST | `/api/projects/:id/reset` | 一键还原：从原始快照恢复全部文件，清空标记/便签/锁定/历史 |
| DELETE | `/api/projects/:id` | 删除项目（目录自包含，连同 .centdeck 快照与历史整体移除，不可恢复） |
| GET | `/api/projects/:id/assets` | 素材列表 |
| POST | `/api/projects/:id/assets` | `{ filename, dataBase64 }` 保存素材到 assets/ |
| GET | `/preview/:id/*` | 项目文件的静态托管（放映模式 iframe 用） |
| GET | `/tpl/:templateId/*` | 模板文件的静态托管（首页模板缩略图用） |

## 4. 项目格式

```
projects/<id>/
├─ project.json      项目名称、模板来源、页面清单、标记、便签、锁定
├─ design/tokens.json 设计规范
├─ pages/*.html       页面源码
├─ assets/            上传的素材
└─ .centdeck/         元数据（不进导出）：pristine/ 原始快照、history/ 历史版本
```

`project.json` 草案：

```json
{
  "id": "my-site", "name": "我的网站", "template": "landing", "createdAt": "...",
  "pages": [{ "file": "pages/index.html", "title": "首页" }],
  "marks": [],   // 草图标记：{id,page,selector,type,data,text,done}
  "notes": [],   // 便签：{id,page,selector,kind:"task"|"rule",text,done}
  "locks": { "pages": [], "elements": [] }  // elements: {page, selector}
}
```

## 5. 内置模板契约（templates/ 下每类一个文件夹）

每个模板必须满足：

- 自带 `project.json`：`{ "id", "name", "type", "description", "pages": [{file,title}] }`。
- 页面放在 `pages/` 下，2~4 页，页间用普通 `<a href="xxx.html">` 互相链接（总览画布的连线靠解析 href 生成）。
- 每页 `<head>` 内有 `<style id="cd-tokens">:root{ --brand: ...; ... }</style>`，正文颜色、字号、间距尽量引用 `var(--*)`，供"设计规范全站生效"测试。
- 纯静态、零外部资源：图片一律内联 SVG（`<svg>` 或 data URI），不引用任何 CDN/外链字体/外链脚本。
- 中文内容，排版美观（这些模板以后就是演示模板）。
- 要素齐全（测试用，尽量都包含）：
  - 标题 h1~h4、正文段落、行内样式元素 与 共用 class 元素（测共用样式误改）；
  - 多个按钮（其中有共用 class 的）、内部页面跳转链接（导航）；
  - 图片（内联 SVG）、表单（input/select/textarea/按钮状态）、列表；
  - 一个 `class="modal"` 弹窗（平时隐藏，按钮触发显示）；
  - 一个用 JS 数组渲染的列表 `<ul id="js-list">`（测红灯：程序生成的内容找不到源码行）；
  - 至少一处 CSS `transform` 动画或 `@keyframes`（测动画通道冲突）。

## 6. 编辑引擎约定（app/js/engine/）

算法最初移植自手动修改演示（已移除，见 Git 历史 `7d3311e`），整理为无副作用的 ES Module，供工作台调用。2026-09-29 重构后：`render.js` 换成 `frame.js`（只负责渲染与双缓冲，交互全部在工作台覆盖层里），`writeback` 新增 `kind:'textNode'`（按"文字段"定位、实体感知、只替换变化的字符）：

- `parse(html)` → 元素清单：selector（ nth-of-type 路径）、源码行列范围、类型、是否 JS 生成、动画通道占用情况。
- `render(iframe, html)` → srcdoc 渲染；返回编辑层句柄（hover 轮廓、选中框、路径条数据）。
- `applyEdit(source, edit)` → `{ light: "green"|"yellow"|"red", newSource?, affected?, reason? }`。
  - 只改被修改元素所在行；挪位写 `translate`、缩放写 `scale`，不碰 `transform` 动画；
  - 红灯：跨区域移动、JS 生成元素、多处相同文字、改排列方式；
  - 黄灯：带出 affected 元素清单（被挤动/被盖住）；
  - 引擎不改共用 class 样式，除非显式 `scope: "class"`。

## 7. 界面要求

- 全中文界面；风格安静干净：灰白底、把颜色留给页面本身。
- 这些功能都做成"内置插件"形态：每个模块（sketch/notes/assets/tokens）向 `bus.js` 注册命令、向 main.js 注册面板，不硬编码进内核。
- 顶部工具栏：项目切换、视图（总览/编辑/放映）、撤销/重做、保存状态、**一键还原**（红色、带二次确认）。
- 性能：拖动 60fps（视觉层 transform 实现，松手才回写）；选中反馈 <0.1s；改完刷新 <1s。
