# Skills 隐藏与规范核查

## 实际原因和修复

本机 8420、8421 两个旧进程返回的官方技能数据都有 `source: builtin`，但没有后来添加的 `internal` 字段。原界面只检查 internal，因而继续显示官方技能。助手会话的预选技能标签也没有统一过滤。

- 用户管理接口 `/api/skills`、`/api/extensions` 的 skills 字段只返回可管理的自定义/扩展技能。
- Skills 管理页、助手配置、聊天选择器共用来源和身份判断，兼容旧进程没有 internal 的数据。旧会话恢复或内部功能预填的官方技能不显示为可移除标签。没有自定义技能时不显示助手的技能选择区。
- AI 的 `list_skills`、`read_skill` 和 MCP 技能资源仍保留全部基础技能。基础技能忽略历史停用设置，接口拒绝停用、删除和覆盖；用户无需选择即可使用。
- 平台指南自动注入任务，其他技能的 ID、说明作为目录提供给模型，由模型按当前任务读取正文。默认可用不等于每轮把所有正文重复加载。
- 更新前检查两个服务均无运行中任务，随后通过应用重启接口更新两个进程。实际验证用户技能列表为空（本机没有自建技能），停用 platform-guide 返回 403。前端已打开页面需刷新以加载新模块。

## 规范审阅结果

审阅并修订 7 个 app/skills 技能及官方项目巡检技能：

| 技能 | 主要修正 |
|---|---|
| platform-guide | 明确内置任务与外部 MCP 的工具边界、projectId 差异、版本写回示例、按任务读取技能、暂停/截断和真实验收要求。 |
| page-edit | 当前源码与唯一目标定位、共享样式影响、手机坐标/媒体查询、版本冲突后重读。 |
| apply-marks | 区分 marks、canvasNotes、notes；按稳定 ID 核对颜色/编号，处理补号和换色，不自动清除用户标记。 |
| design-system | 明确保存 tokens、应用页面与创建卡片是不同动作；不虚构内置助手没有的卡片/个人预设工具。 |
| design-variants | 不强制多方案；提供符合当前 publish_variant 格式的示例、全站 scope 要求、独立目录和资源路径处理。 |
| tidy-import | 不承诺格式化后任意框架都可编辑；保留框架、资源与交互，仅处理用户指定障碍。 |
| centdeck-orchestrate | 明确实际 delegate 参数、依赖 ID、一层分派、主任务没有 wait 工具、不将派发当作完成。 |
| official-inspector--review | 统计只作线索，不能代替提交/源码/浏览器证据；内置任务没有 ui_action。 |

原来 5 个技能引用 `../rules.md`，但技能工具并不支持读取这个宿主路径。现在共用规范统一通过 `read_skill({"id":"platform-guide"})` 获取；旧 rules.md 只为直接读源码的开发者保留入口。

工具注册表的展示方式和执行工具未在本轮调整。技能说明以实际工具 Schema 为准，不通过说明文件扩大权限或补造能力。

## 验证

- 七个 SKILL.md 均通过 skill-creator 的格式验证。
- skills.test：旧数据过滤、旧会话技能标签、基础技能不可关闭/删除/覆盖、历史停用与同 ID 覆盖数据、用户自建技能启停、AI/MCP 可发现与读取基础技能、跨技能调用均通过。
- agent-runtime：26 组通过，新增用户管理接口隐藏及基础技能保护回归。
- extensions、mcp-transport、external-runtime、前端 57 个模块语法检查通过。

以上证明分流、保护和工具链可用；没有把本机协议测试冒充真实模型行为评估。当前未新增真实供应商联调或浏览器截图验收。
