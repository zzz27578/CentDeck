# MCP 实测问题修复

针对 [余白 MCP 实测报告](余白MCP实测_2026-10-01.md) 的五项缺口进行修订。保留本地双击启动、零项目安装依赖的交付方式。

## 修改内容

| 原问题 | 修复 |
|---|---|
| 能读 DESIGN.md，不能写 Markdown | write_files / patch_text 现在允许项目内 .md；保持路径、版本、scope、锁定和多文件事务检查。 |
| 已有页面 title 参数被忽略 | write_files 可更新已有页面清单标题；新增 rename_page，修改显示名称而不改文件路径或 HTML title。页面名称同样有并发校验和撤销保护。 |
| projectId 未声明必填 | 项目文件、上下文、截图、重命名和项目插件工具的外部 MCP Schema 明确 required projectId；运行时也返回清楚的缺参错误。全局技能和客户端发现保持无需项目。 |
| 刷新后旧客户端与控件失效不清晰 | 刷新复用标签页客户端身份，控件 ID 包含文档版本；旧操作失效时返回 DOCUMENT_REPLACED / STALE_CONTROL，多标签页不明确时要求 clientId。不会把旧操作自动发到另一个标签页。 |
| 页面操作中停止心跳 | 心跳与操作队列分开；后台延迟状态保留 90 秒并报告连接年龄。回执失败可重传，重复命令不重复执行；过期的排队命令不在稍后执行。 |
| 看不到 iframe 内容、表单和尺寸 | 编辑页 ui_state 新增 preview，可见文字、标题、视口/滚动尺寸、水平溢出标志及内部控件；click/fill/scroll 可操作这些控件，填写触发原生 input/change 事件。密码、上传、私密字段受到保护，弹窗开启时只能操作当前弹窗。 |
| 没有截图 | 新增 capture_page，使用已安装的 Edge/Chrome 在独立临时配置中渲染项目，返回标准 MCP PNG 图像及真实视口尺寸。无需接管用户桌面或个人浏览器配置。 |
| 后台标签页打开页面一直等待 | 实测发现 requestAnimationFrame 在后台可能暂停。预览渲染增加定时兜底，状态明确报告 ready，避免空白中间页面被误认为完成。 |

## 新工具示例

```json
{"name":"read_page","arguments":{"projectId":"yubai-mcp","path":"index.html"}}
{"name":"rename_page","arguments":{"projectId":"yubai-mcp","path":"index.html","title":"余白 · 首页","baseHash":"上一步返回的值"}}
{"name":"capture_page","arguments":{"projectId":"yubai-mcp","path":"index.html","width":393,"height":852}}
```

ui_state 的控件带 `context: workbench / preview`。针对网页内部交互，先 open_page，再从 preview.controls 取实际 ID。每次切页、刷新或动态表单更新后重新取状态。不要缓存旧控件号重放操作。

## 明确边界

capture_page 是 **fresh-project-render**：渲染指定项目的初始页面，只加载项目本地和内嵌资源。它不是在线标签页截图，不包含当前表单或点击状态，不会冒充对交互后的画面取证。远程图片/字体可能缺失；需结合在线控件状态检查。

当前浏览器标签页一度处于隐藏状态，旧前端等待动画帧导致在线操作超时；已据此加入兜底与回归。网页控件读取与弹层隔离已在实际服务验证；填写、筛选和事件触发通过组件测试。用户正在填写模型设置时没有关闭该表单继续测试，因此尚不声称整条在线表单交互已验收。

缺少本机 Edge/Chrome 时截图会明确报错，可用 CENTDECK_CAPTURE_BROWSER 指向已安装浏览器。浏览器被系统冻结、标签页关闭或连接超时时，工具报告结果未知并要求核对，不擅自重放写操作。
